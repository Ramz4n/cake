# Портфолио кондитера — правила проекта

## О проекте
Персональный сайт-визитка кондитера: фото работ, немного о мастере, отзывы, контакты для заказа. Целевая аудитория — потенциальные заказчики тортов и десертов, заходящие с телефона (Instagram/WhatsApp в первую очередь).

## Стек
- Чистый **HTML/CSS/JS**, без фреймворков и сборщиков (Vite, React и т.п. не нужны).
- Никакого бэкенда/сервера — сайт статический, деплой на GitHub Pages / Netlify / Vercel.
- `main.py` — неиспользуемый файл-заглушка от PyCharm, к сайту отношения не имеет.

## Структура файлов
```
/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── script.js
├── images/
│   ├── works/        # фото готовых работ (торты, десерты)
│   └── portrait/      # фото кондитера
└── CLAUDE.md
```
Один HTML-файл на страницу (сайт одностраничный, если не решим иначе). Секции внутри index.html через `<section id="...">`.

## Разделы страницы
1. **Работы (scroll-gallery)** — с самого начала страницы: фото «прилипает» на весь экран (position: sticky) и сменяется на следующее при скролле вниз. Первый слайд несёт заголовок/слоган/CTA поверх фото (замена классического Hero), остальные слайды — просто фото работ. Реализовано через IntersectionObserver (см. js/script.js), без сторонних библиотек.
2. **Обо мне** — фото кондитера, короткий текст об опыте.
3. **Контакты** — телефон, соцсети/мессенджеры, кнопка «Написать».

Раздел «Отзывы» на сайте не нужен (сознательное решение, не добавлять).

## Дизайн
- Тёплая, «вкусная» палитра (кремовые, пудровые, шоколадные тона), не кричащая.
- Акцент на фото — они главный контент, текста минимум.
- Mobile-first: сначала верстаем и проверяем на узком экране.
- Простые читаемые шрифты, без лишней анимации, отвлекающей от фото.

## Изображения
- Оптимизировать перед добавлением (сжатие, разумный размер — не выкладывать фото «как есть» из телефона).
- Формат `.jpg`/`.webp`, у каждого `<img>` — осмысленный `alt`.
- Ленивая загрузка (`loading="lazy"`) для фото галереи ниже первого экрана.

## Прочее
- Язык интерфейса — русский.
- Код без комментариев, кроме случаев неочевидной логики.
- Семантическая вёрстка (`header`, `main`, `section`, `footer`), без лишних `div`.
